Architecture Notes

Interpretation of the code structure and runtime responsibilities

Request Path

HTTP requests enter Spring MVC controllers, pass through JWT/OIDC security, and are delegated to business services. Services coordinate domain rules and repositories, while DTOs define the API boundary.

Persistence

Domain entities and repositories use Spring Data JPA/Hibernate. PostgreSQL is the production store; H2 supports local development and tests. Flyway migrations are enabled for PostgreSQL profiles.

Business Scope

The application groups capabilities by ERP domain: master data, organization, commercial flows, finance, HR/payroll, agriculture, manufacturing, processing, inventory, logistics, quality, reports, and workflow.

Security & Tenancy

Local authentication issues JWTs. OIDC providers can be verified and exchanged for application sessions. Tenant and user context are shared application concerns used across protected operations.

Scheduled Work

In-process schedulers handle business maintenance and optional field-IoT synchronization. This means background execution scales with the application instance, not a separately deployed worker.

External Integrations

AI provider adapters support Gemini, Anthropic, and OpenAI-compatible APIs. Other integrations cover SMTP email, Twilio SMS/WhatsApp, and weather/satellite field data.

Deployment Model

The Dockerfile uses a Maven build stage and a smaller Temurin runtime stage. Railway activates the railway Spring profile. Environment variables provide deployment-specific credentials and endpoints.

Architectural Trade-off

This is a modular monolith rather than a microservice system: one deployment simplifies transactions and operations, while package boundaries provide an initial path for future extraction.
